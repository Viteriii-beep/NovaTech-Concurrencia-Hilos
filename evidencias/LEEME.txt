EVIDENCIAS DE EJECUCION
=======================
Capturas de pantalla de las corridas del programa.

01_resumen_final_integridad.png
   Comando: python main.py
   Muestra el resumen final: 23 procesados, 16 aprobados, 4 rechazados,
   3 errores, 10.98 s, 4/4 hilos y las cinco verificaciones de integridad
   en [OK]. El inventario final cuadra con las 47 unidades aprobadas.
   Evidencia de: CP-05 (cierre limpio) y criterio de integridad.

02_hilos_trabajando_en_paralelo.png
   Comando: python main.py  (parte media del registro)
   Los tres trabajadores inician sus pedidos en el mismo milisegundo
   (02:56:16.874, .874 y .875), lo que solo es posible con hilos reales.
   Incluye los rechazos por contencion en P005 y P004, el rechazo de
   ORD-014 por stock insuficiente en P003, y ORD-007 aprobado con dos
   productos descontados juntos.
   Evidencia de: CP-01, CP-02 y CP-03.

03_inventario_negativo_sin_candado.png
   Comando: python main.py --sin-lock --workers 6
   Modo de demostracion con el candado desactivado. P004 quedo con
   existencia final -1: se vendieron 9 camaras web habiendo 8. La
   verificacion marca [FALLA]. Es la prueba de que la sincronizacion
   es necesaria y no un adorno.

04_un_solo_trabajador_tiempo.png
   Comando: python main.py --workers 1
   29.15 s con 2/2 hilos. El unico trabajador atendio los 23 pedidos.
   Mismo resultado que con tres trabajadores (16/4/3, 47 unidades):
   la concurrencia cambio el tiempo, no el resultado.

05_comparacion_tiempos_1_vs_3.png
   Comandos:
     1..3 | ForEach-Object { python main.py --workers 3 | Select-String "Tiempo total" }
     1..3 | ForEach-Object { python main.py --workers 1 | Select-String "Tiempo total" }
   Tres corridas de cada configuracion:
     3 trabajadores: 10.97 / 11.35 / 9.64   -> promedio 10.65 s
     1 trabajador  : 30.58 / 30.87 / 30.08  -> promedio 30.51 s
     Mejora promedio: 2.86 veces

NOTA
El orden exacto de los mensajes cambia entre ejecuciones, y los tiempos
tambien, porque la duracion de cada pedido se sortea entre 0.5 y 2
segundos. Esa variacion es normal en un programa concurrente. Lo que no
varia es la integridad de los datos.
